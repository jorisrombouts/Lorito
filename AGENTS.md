# Lorito: rules for changing the code

What it is, how to install and use it: `README.md`. This file is what keeps a change from breaking the app.

## Docs

- After a change, check `README.md` and this file; rewrite only a sentence the change made wrong. Replace and delete before adding; no history, no changelog, no rationale a user does not need. The README's size and speed figures are measurements (`wc -l Sources/Lorito/*.swift`, `du -sh` on the installed binary, the log); a code change re-measures them.
- A change a user notices gets one line under Unreleased in `CHANGELOG.md`; a release turns that heading into the version and date and bumps `CFBundleShortVersionString` in `build-app.sh`.

## Build and test

- `./build-app.sh` builds release, signs, and restarts `build/Lorito.app`. `./build-app.sh install` refreshes `/Applications/Lorito.app`, the login item. Never replace a bundle under a running app: macOS silently drops its permissions. Never run both copies at once.
- Sign with the "Lorito Dev" certificate (`make-signing-cert.sh`). An ad-hoc signature is a new identity per build, and every permission grant dies with it.
- `./check.sh` is the smoke test: `--self-test` (cleanup and Thorough guards, sentence windows, cleanup-level migration, hotkeys, clipboard restore; also what CI runs, since CI has no model or Apple Intelligence), engine on English, Dutch, noise, a hum it must hear no speech in and a spoken "thank you" it must keep; cleanup on Dutch and on a question it must not answer; Thorough on a repeat, a filler, a clean question and an injected instruction; overlay render. Run it before merging. The paste, hotkey and hands-free paths are checked by hand; `--insert-test` pastes into the frontmost app and the log's `mode=` field shows the gesture.
- Log: `~/Library/Logs/Lorito.log`, moved to `Lorito.old.log` at 1 MB; it never holds dictated text. Baseline on an M4 Pro: engine load 0.1 to 0.2 s (12 s on the first launch of a new build while Core ML compiles the models, plus the download the first time ever), recognition 0.05 to 0.2 s per dictation, cleanup 0.3 s plus 25 ms per second of audio. Far above these is a regression.
- The models live in `~/Library/Application Support/FluidAudio`, downloaded by FluidAudio from Hugging Face on first launch; "engine failed" in the log with the menu showing the reason means that download did not land. FluidAudio's API is the source in `.build/checkouts/FluidAudio`; docs.fluidinference.com lags it by several versions.

- The Command Line Tools ship no SwiftUI macro plugin and cannot load the Swift Testing macros: no `@State`, no `@Entry`, no test target. Use `@AppStorage`, the `@Observable` controller, and checks in `SelfTest.swift`.

## Permissions

- A paste that does not land is Accessibility, not code: `TextInserter.insert` returns the reason and the pill shows it instead of "Inserted". `ax_trusted=0` in the log with the app enabled in System Settings means a stale entry: `tccutil reset Accessibility nl.joris.lorito`, relaunch, grant again. A binary started from a shell inherits the terminal's grants; only `open` tests the app's own.
- Secure Event Input (a password field, a terminal's Secure Keyboard Entry) stops both the recording and the paste; the pill says so.
- The agent sandbox cannot read `log show` or take screenshots. Use the log file and `--overlay-demo`.

## Code

- SwiftUI instantiates the `App` struct more than once: the controller is a singleton, started on `didFinishLaunching`.
- Top-level `Task {}` in `main.swift` runs on the main actor; blocking main with a semaphore deadlocks it. Harness code uses `RunLoop.main.run()` or `Task.detached`.
- The hotkey is a modifier key from `Hotkey` in `Settings.swift`, told left from right by the device-dependent flag bits; `HotkeyMonitor` reads it per event, so Settings applies at once. Left Option stays the default.
- First launch, and the menu's "Set Up Lorito…" when something is missing, open `OnboardingWindow`; Settings › Permissions shows the same `SetupRows`. Both are plain grouped `Form`s in system style with the app icon on top, and the app activates itself before opening either, being `LSUIElement`.
- `TextInserter` saves every pasteboard item and type, marks the dictation `org.nspasteboard.TransientType`, and restores after 0.6 s unless something else was copied meanwhile.
- Recording uses `AVCaptureSession` with an explicit `AVCaptureDeviceInput`; `AVAudioEngine` cannot bind a device reliably (Bluetooth headsets renegotiate their sample rate right after the mic opens). The converter is rebuilt when the buffer format changes and lives on the audio queue only; the session starts and stops on its own serial queue (`startRunning` blocks for about 70 ms). A disconnect or runtime error ends the dictation with what was captured.
- The level meter in `DictationController` tracks a noise floor and a recent peak with tuned constants; recorded silence must give zero. The peak starts at zero per dictation so the first syllable sets it: a peak carried over from a loud ending, or started above a soft voice, leaves the bars flat until it decays past the voice. The dictation log line carries the meter's floor, peak and highest level.
- Parakeet returns empty text for noise, hum and clicks on its own, with no VAD in front of it; `check.sh` holds that. A fresh `TdtDecoderState` per dictation keeps one dictation from leaking into the next.
- FoundationModels wants to answer a dictated question and translate a foreign one; the instructions forbid both, and the examples carried as past turns in the session `Transcript` show it. Write every example the way the engine hands text over, punctuated and capitalised: lowercase examples teach the model that tidy-looking input needs no edit, and it hands a filler-ridden sentence straight back. It applies a marked self-correction ("no wait") reliably and an unmarked restart ("What, why") in neither direction, inventing ungrammatical text when pushed, so the prompt leaves those alone. Never use the same text as an example and a test; a duplicate prompt makes the model answer it. `Cleaner.plausible` rejects output whose length or vocabulary strays from the transcript, which catches an answer that slips through. Verify with `--clean`.
- Settings has one Cleanup picker (`CleanupLevel`: off, standard, thorough); `Settings.cleanupEnabled` and `polishEnabled` derive from it, and `Settings.migrateCleanup` carries over 1.2's two switches at launch. Thorough (`Cleaner.polish`) is a second session over the cleaned text, three sentences at a time (`Cleaner.windows`): given a long text whole, the model hands it back untouched. It may only delete, and `Cleaner.onlyDeletes` enforces that per window: the output's words are the input's in order, and every deleted run is a hesitation, a filler phrase set off by a comma, a copy of the words right before or after it, or a whole sentence of at most four words ending on a word like "is" or "dat" with no number or negation. Leading and trailing whitespace of each window is kept, so blank lines and emoji survive the join. Tokens keep inner separators and symbols, so 3,5 to 3.5 or € to $ fails. Asked to keep punctuation, the model splits ", and" into ". And"; asked not to touch it, it stops deleting repeats. It leaves many leftovers alone, which is the safe direction. Verify with `--polish`; `check.sh` holds a repeat, filler, a clean question and an injected instruction.
- The cleanup session is rebuilt and prewarmed when recording starts: macOS evicts the model after idle, and a cold call takes over 2 s, past the timeout, which reaches the pill as "Raw text inserted".
- Overlay: the `NSPanel` has a fixed generous transparent frame and never activates; the SwiftUI pill is a Liquid Glass capsule (`glassEffect`) that sizes itself inside it, and the hands-free ✕ is a tap gesture, not a button. `ProgressView` does not render in a non-activating panel. `--overlay-demo` renders through an `NSHostingView` because `ImageRenderer` drops a glass-effect view; the glass itself never appears offscreen, so judge the capsule on screen. The app icon, the menu bar glyph and the pill's parrot are one drawing, `LoritoApp.parrot`: `build-app.sh` renders the icns from the binary (`--icon`), and the drawing samples its paths at 680 pt whatever the output size, because SwiftUI `Path.contains` flattens curves with an absolute tolerance and moves bar tops at 18 pt. The pill's parrot keeps the icon's colours and `isTemplate` off; the level bars are `Color.primary`, since a plain `.primary` fill turns vibrant white under glass. Every other icon is an SF Symbol, and the menu bar stays monochrome. Animations ignore Reduce Motion by design.
- The start and stop sounds (`Chime`) are macOS's dictation sounds, `dt-begin` and `dt-confirm`, read from the private AssistantServices framework; Tink and Pop stand in when a macOS update moves them. Apple's sound files are never copied into the repo.
